# Contributing to Foundation

Thank you for your interest in contributing to the foundational layer of Altman Family Group.

This repository is the single source of truth for how we think, decide, and build. Contributions here carry more weight than code in product repositories because they shape the principles that guide everything else.

## Our Standards

Before submitting anything, ask yourself:

- Does this strengthen **human dignity**, **truth**, and **verifiable positive impact**?
- Does it align with the **P-A-I-H-I Framework**?
- Is this clear, honest, and useful — or is it clever for the sake of cleverness?
- Would I be proud to have future team members and collaborators read this in five years?

We hold contributions to foundation to a higher bar than typical open source. This is intentional.

## How to Contribute

1. **Start with an issue**  
   Open an issue first (even for small changes). Use a clear title and explain the “why” before the “what.” Reference the relevant section of the README or P-A-I-H-I framework.

2. **Align with principles**  
   In your issue or pull request, briefly state how your change supports at least one of the Core Principles or improves the P-A-I-H-I framework.

3. **Keep it focused**  
   One clear idea per pull request. Large sweeping changes should be broken into smaller, reviewable pieces.

4. **Write for humans first**  
   Documentation and proposals should be readable by a smart non-engineer. Clarity beats technical density.

5. **Human review is final**  
   AI tools are welcome as accelerators. Final decisions on philosophy, direction, and wording are made by humans.

## Pull Request Process

- Fork the repository and create your branch from `main`.
- Make your changes.
- Submit a pull request with a clear description of the change and its alignment to our principles.
- Be responsive to feedback. We move fast but we do not rush foundational decisions.

## What We’re Looking For Right Now

- Refinements and real-world stress tests of the P-A-I-H-I framework
- Clearer language in the Core Principles
- Decision frameworks or playbooks that help future teams apply these principles
- Improvements to how this repository is organized and discovered

We are especially interested in contributions that make these principles more actionable and testable in actual product work.

## Questions?

Open an issue with the label `question` or reach out directly. We would rather have a good conversation than a technically perfect but misaligned contribution.
